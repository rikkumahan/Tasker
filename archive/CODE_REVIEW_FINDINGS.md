## 1. Correctness bugs

### 1.1 `delete-account` missing service-key fallback
`supabase/functions/delete-account/index.ts:14-17`

Every other function resolves the service key as `Deno.env.get("MY_SERVICE_ROLE_KEY") ?? Deno.env.get("SUPABASE_SERVICE_ROLE_KEY")`. This file only reads the old var:

```ts
const supabaseAdmin = createClient(
  Deno.env.get("SUPABASE_URL") ?? "",
  Deno.env.get("SUPABASE_SERVICE_ROLE_KEY") ?? "",
  { auth: { autoRefreshToken: false, persistSession: false } }
);
```

If the deployed env only has `MY_SERVICE_ROLE_KEY` set, `supabaseAdmin` gets an empty key and `supabaseAdmin.auth.admin.deleteUser(uid)` silently fails on every account-deletion request.

Fix: `Deno.env.get("MY_SERVICE_ROLE_KEY") ?? Deno.env.get("SUPABASE_SERVICE_ROLE_KEY") ?? ""`

### 1.2 Stale date computed at module load
`TaskerAI/app/(tabs)/index.js:13-15`

```js
const dateString = new Date().toLocaleDateString('en-US', {
  weekday: 'long', month: 'long', day: 'numeric', year: 'numeric',
});
```

Runs once when the JS bundle loads, not per render. A resident mobile app that stays open across midnight shows yesterday's date in the header.

Fix: compute inline in the component (cheap enough to skip memoization) instead of at module scope.

### 1.3 Fragile string-based "waiting over 24h" check
`TaskerAI/app/(tabs)/index.js:64`

```js
const waitingOver24h = threads.filter(t => t.action_type === 'reply' && t.timeAgo.endsWith('d')).length;
```

Infers "over 24h" from a display-formatted string (`timeAgo`, e.g. `"3d"`). Breaks silently if the formatter changes suffix, and misses `1w`/`2w`+ values entirely (undercounts).

Fix: derive from the raw timestamp instead of the formatted string.

## 2. Dead code

### 2.1 `_shared/stages.ts` — entire file unused (527 lines)
`supabase/functions/_shared/stages.ts`

Exports `extractRawTasks`, `evolvePersonaFromTasks`, `categorizeTasks`, `runWarningEngine` — grepped every caller across `TaskerAI/`, `supabase/`, `execution/`, `directives/`; nothing imports this file except itself. The active pipeline (`sync/index.ts`) uses `GraphRAGStore`/`ActionContextBuilder`/`ActionExtractor`/`ActionReconciler` from `graph.ts`/`actions.ts` instead.

**Action: delete the file and the `@arcjet/redact` import.** −527 lines, −1 dependency.


### 2.3 `mockData.js` fallback branches are unreachable
`TaskerAI/components/mockData.js` (367 lines, header says "Replace with real API calls in Phase 2" — that migration already happened)

```js
// TaskList.js:192
const sourceData = data || TASKS;
// PeopleGrid.js:357

// DashboardCards.js:95-96
```

## 3. Duplication worth consolidating

### 3.1 Auth nav-guard duplicated between layouts
`TaskerAI/app/_layout.js:9-72`, `TaskerAI/app/_layout.web.js:14-83`

`ONBOARDING_ROUTES` and the entire session/wizard-step redirect `useEffect` are copy-pasted verbatim (web version adds an OAuth-hash guard on top). Two files to keep in sync for any routing rule change.

**Suggested:** extract to `TaskerAI/hooks/useAuthGuard.js`, taking an optional `extraSkipCondition` for the web-only case. ~30 fewer lines.

### 3.2 Data-sync effect duplicated
`TaskerAI/app/_layout.web.js:30-49`, `TaskerAI/app/(tabs)/_layout.js:37-54`

Identical effect (`fetchAll()` / `initRealtime()` / `destroyRealtime()` on `session.user.id`) in both files.

**Suggested:** `TaskerAI/hooks/useAppDataSync.js`, called from both layouts.

### 3.3 Selection + panel state block copy-pasted 3x
`TaskerAI/app/(tabs)/index.js:32,73-86`, `tasks.js:20,25-38`, `waiting.js:31-32,42-55`

```js
const [selectedId, setSelectedId] = useState(null);
const [panelVisible, setPanelVisible] = useState(false);
const selectedItem = useMemo(() => threads.find(t => t.id === selectedId) ?? null, [selectedId, threads]);
const handleSelect = useCallback((id) => { setSelectedId(id); setPanelVisible(true); }, []);
const handleClose = useCallback(() => { setPanelVisible(false); setSelectedId(null); }, []);
```

**Suggested:** `hooks/useItemPanel(list)` returning `{ selectedItem, panelVisible, handleSelect, handleClose }`. ~30 fewer lines total.

### 3.4 Centered loading spinner duplicated 3x
`TaskerAI/app/(tabs)/index.js:119-125`, `waiting.js:61-67`, `projects.js:53-59`

Identical `ActivityIndicator` early-return block. **Suggested:** a shared `<CenteredSpinner />` component.

### 3.5 `EmptyState` duplicated verbatim
`TaskerAI/app/(tabs)/waiting.js:13-28`, `projects.js:28-43`

Same layout + identical `StyleSheet.create` block, differing only in copy text. **Suggested:** `components/EmptyState.js` taking `heading`/`sub`/`icon` props. (Note: `people.js` has no empty state at all — worth checking that's intentional.)

### 3.6 Account-action logic duplicated between `ProfileSheet.js` and `web/Sidebar.js`
`TaskerAI/components/ProfileSheet.js:74-130`, `TaskerAI/components/web/Sidebar.js:108-141`

`handleSync` and `handleDeleteAccount` independently implemented — same Supabase calls, same confirm/alert flow — just copy-pasted with `Platform.OS` conditionals stripped in the web copy.

**Suggested:** shared `TaskerAI/hooks/useAccountActions.js` hook.

### 3.7 `getInitials` hand-rolled 3 different ways — and they disagree
`TaskerAI/components/UnifiedPageHeader.js:93-100`, `ProfileSheet.js:67-72`, `web/Sidebar.js:104-106`

`UnifiedPageHeader.js`/`ProfileSheet.js` strip quotes and use first+last initial; `web/Sidebar.js` doesn't strip quotes and takes the first letter of *every* word. For names like `'"Bh - Seethanagaram [Union Bank Of India]"'` these produce visibly different initials depending on which screen you're on — a real user-facing inconsistency, not just style debt.

**Suggested:** one shared `getInitials(fullName, fallback)` in `TaskerAI/lib/initials.js`.

### 3.8 JWT-decode-with-fallback duplicated instead of reusing `_shared/auth.ts`
`supabase/functions/sync/index.ts:148-184`, `supabase/functions/synthesize_profile/index.ts:27-46`

`_shared/auth.ts` already exports `authenticateUser()` (manual JWT decode + Supabase API fallback), used correctly by `api/index.ts` and `query/index.ts`. `sync` and `synthesize_profile` each reimplement the identical ~25-line block inline.

`synthesize_profile` doesn't need the service-role path, so it can call `authenticateUser()` directly. `sync` needs a service-role bypass (for `background_worker` calling with `user_id` in body) — worth adding an optional service-role check to `authenticateUser` instead of keeping a second full copy.

### 3.9 `bootstrapUser` / `checkSyncHealth` near-duplicate state machines
`TaskerAI/store/authStore.js:172-229` (`bootstrapUser`), `:231-288` (`checkSyncHealth`)

Both guard on a trigger flag, set `isLoading: true`, query `onboarding_status`, then branch on the same three cases (`complete` / in-progress / new-user). ~55 lines duplicated almost line-for-line; differs only in column selection and provider-token resolution for the "new user" case.

**Suggested:** shared helper (e.g. `_resolveOnboarding(session, settings)`), each caller keeps only its caller-specific bits. Low priority — only worth doing next time either function is touched.

### 3.10 `markRead` / `toggleStar` duplicate the optimistic-update pattern
`TaskerAI/store/appStore.js:167-213`

Both do: snapshot `threads`, optimistically patch, `await supabase.update`, revert on error. **Suggested:** shared `_optimisticThreadUpdate(threadId, patch, revertPatch, label)` helper. Low priority, current code is correct, just repetitive.

- **`TaskerAI/constants/navItems.js:13`** — `badge: 4` on the "waiting" nav item is dead; every consumer (`web/Sidebar.js`, mobile tab layout) overrides it with a live count before display.

- **`TaskerAI/components/TaskList.js:249-262`** — `renderItem` passed to `FlatList` is an inline arrow function (recreated every render, e.g. every search keystroke) calling `useAppStore.getState().toggleStar` per item instead of a selector; `PriorityRow` isn't `React.memo`'d either, so every row re-renders on every keystroke. Same shape (lower priority) in `PeopleGrid.js:375`.
